# تقرير جرد — نقل «نايوش لتحليل البيانات» إلى NAIOSH LAW

تاريخ الجرد: 2026-10-28 (Africa/Cairo)  
المصادر: `naioshapp26-ship-it/naiosh-hub` · `naioshapp26-ship-it/naiosh-intelligence`

## الخلاصة

| المصدر | الدور الحقيقي |
|--------|----------------|
| **HUB 360** (`quality-analysis.html`) | بوابة تسويق وربط فقط — **لا محرك تحليل داخل هوب** |
| **NAIOSH Intelligence** (`www.naioshai.com`) | النظام الوظيفي الحي: واجهة + API + رفع ملفات + محرك تحليل في المتصفح |

الصورة المرفقة لصفحة هوب؛ الأزرار تفتح النظام المستقل خارجيًا. النقل الوظيفي يجب أن يعتمد على **Intelligence** مع تكييف قانوني داخل LAW، وليس نسخ صفحة هوب الشكلية.

## 1) ما يوجد فعليًا في HUB 360

| المسار | الوظيفة |
|--------|---------|
| `quality-analysis.html` | الصفحة الرئيسية «نايوش لتحليل البيانات» (Hero + بطاقات) |
| `css/hub-data-analysis.css` · `css/hub-da-intel-hero.css` | تنسيق البوابة |
| `js/hub-data-analysis.js` | إعادة كتابة روابط CTA إلى `naioshai.com` |
| `js/hub-live-systems.js` → `ANALYSIS` | سجل النظام الحي |
| `docs/data-analysis-portal-delivery.md` | يؤكد صراحة: «لا محرك تحليل داخل هوب» |

**غير موجود في هوب:** APIs تحليل، رفع ملفات، حساب مؤشرات، تقارير، صلاحيات بيانات.

## 2) ما يوجد فعليًا في NAIOSH Intelligence (المحرك)

### خادم (Node + SQLite)
- `src/routes/auth.js` · `accounts.js` · `requests.js` · `users.js` · `ledger.js` · `content.js` · `messages.js` · `qa.js`
- رفع مرفقات، طلبات تحليل، تقارير مختومة، محفظة نقاط، تدقيق متسلسل

### محرك التحليل (يعمل في المتصفح)
- `frontend/src/08d_analytics.html` — تحليل CSV/XLSX + 10 أنواع حسابية حقيقية (وصفي، تشخيصي، تنبؤ، جدوى NPV/IRR، …)
- `08da_readers.html` — قراءات متعددة الصيغ
- `08e_results.html` / `08eb_dash.html` — عرض النتائج
- `08b_export.html` — تصدير PDF/Excel من المتصفح
- `08k_legal_ebiz.html` — محرك LEGAL 360 ببيانات **تجريبية محلية** (`LEG-C001…`) — **لا يقرأ قاعدة LAW**

### ما يعمل / ما لا يعمل

| المكوّن | الحالة |
|---------|--------|
| تحليل ملف CSV/XLSX في المتصفح | ✅ يعمل |
| رفع طلبات + مرفقات + تقرير مختوم | ✅ يعمل (سيرفر Intelligence) |
| Auth/أدوار/تدقيق | ✅ يعمل داخل Intelligence |
| نقاط / باقات / شحن / دفع | ⚠️ تجريبي — **لا يُنقل إلى LAW** |
| CNS-001 / اسأل نايوش | 🟡 محاكاة / مطابقة قواعد |
| ربط ERP/CRM/LAW مباشر | ❌ غير موجود (مرحلة ثانية) |
| LEGAL 360 على قضايا LAW الحقيقية | ❌ بذور تجريبية فقط |

## 3) ما يُعاد استخدامه في LAW

1. **منطق محرك المتصفح** (`08d` + أجزاء `08da`/`08b`) كوحدة TypeScript داخل LAW — بدون نقاط ودفع وعلامة Intelligence التجارية.
2. **تكوين الصفحة** (Hero → تعريف → بطاقات → أدوات) مستوحى من هوب، بهوية LAW فقط.
3. **فكرة عزل التخزين والصلاحيات** — لا مشاركة DB/محفظة مع هوب أو Intelligence.

## 4) ما يحتاج تطويرًا جديدًا في LAW

| البند | السبب |
|-------|--------|
| مسار `/app/data-analysis` + مساحة عمل | داخل AppShell وقائمة LAW |
| عنصر قائمة جانبية | غير موجود |
| مصادر بيانات قانونية مصرّح بها | قضايا / جلسات / موكلون / مالية عبر Prisma + دور المستخدم |
| API LAW للبيانات والرفع | صلاحيات LAW وليس حسابات Intelligence |
| هوية بصرية قانونية | شعار وألوان LAW — بدون شعار هوب/أحمر Intelligence وبدون 300 نقطة |
| عزل العملاء | لا تسرّب بيانات موكل لغير المخوّل |
| عدم نقل التجارة | لا نقاط ترحيب / باقات / دفع |

## 5) قرار المعمارية المعتمد للتنفيذ

- **لا نسخ كامل لمستودع Intelligence** داخل LAW.
- **استخراج محرك التحليل الجدولي** وتشغيله داخل مساحة عمل LAW.
- **تغذية المحرك** من: (أ) مجموعات بيانات قانونية مصرّح بها عبر API LAW، أو (ب) رفع CSV/Excel بعد التحقق.
- **فصل كامل** للتخزين والصلاحيات عن HUB/Intelligence.
- **استبعاد** عروض التجربة المجانية والتسعير والنقاط إلى حين موافقة مستقلة.
